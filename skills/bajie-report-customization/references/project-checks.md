## 分清四类改动

| 需求表现 | 要查的证据 |
| --- | --- |
| 改固定文案、排版或复用已存在的字段 | 查对应模板分支、接口响应及实际编辑保存能力。布局移动、标签改名也要核对保存参数或事件映射。 |
| 新增医院专用版式 | 查新报告如何从机构配置取得模板编号并写入报告，后端是否已通用支持。若已有正确配置且可复用模板，核实是否仅需前端；如果需要新编号，另判定配置改动。 |
| 改评估建议、阈值或条件文字 | 查机构专属模板和默认模板、`sleep_report_suggest_template` 的占位符、`sleep_suggest_condition` 的匹配及后端条件码识别。区分前端局部展示和后端真实生成内容。改共享默认模板会影响其他机构，新增占位符前核实后端是否已识别。 |
| 新增业务字段、校验或生成规则 | 从录入、接口、配置、存储到新报告生成和编辑逐段核实。复用已有列和接口须有证据；确有缺口时分别给出 Java、DDL 及配置数据的改动。涉及多个端时明确各端是否在本期。 |

## 两库只读核查

- 使用已有授权的只读连接或已配置的 Navicat，通过最小范围的只读查询核实环境、目标有效机构及其部门、配置、编号占用和必要的表结构。以环境加机构身份核对，不能假定测试与生产的同一机构 ID 对应同一机构。只读阶段不改数据、连接权限或网络配置，不读取无关患者明细。
- 普通睡眠报告先核对 `sleep_hospital_setup` 中机构的 `report_template_type`，再核对报告记录 `sleep_report.report_template_type` 和详情接口 `reportTemplateType`。初筛报告单独核查 `xy_report_template_type`、`sleep_ring_report` 及对应接口。表、配置键和字段均对照当前代码与库结构确认。
- 查新编号时对照前端当前枚举、可见的并行需求和两库的报告记录与机构配置。区分有效占用与历史/已删除记录，核实是否有软删除、重复的有效配置或同名机构，并标明无法核对的来源。未核实的编号只能作为候选。
- 机构默认配置通常作用于新生成报告，现有报告读自身记录里的模板。改既有模板代码可能让历史报告重新打开时换版式；这与修改历史记录、重推或重建旧文件是不同的动作。遇到重推、人工保存或主动清空值的场景，查实际生成规则并记录预期。

## 验收设计

- 无对应测试机构时可只读选一份合适的**同报告类型**测试样例，优先复用专用验收样例，必要时找未占用的模板 0 报告。记录原模板值、样例链接及回退方法；样例切换须有针对测试库的当次授权。切样例能验证指定模板的显示与编辑，不能代替新报告自动取得模板的验收。
- 覆盖目标模板与通用/邻近模板的对照，以及受改动影响的新旧报告、字段空值、保存刷新、人工内容保留等场景。分享、打印和 PDF/PNG 按报告实际支持的入口验收。明确旧缓存文件和新生成文件各自预期，单独记录本地检查、部署确认、真实数据与导出验收。
- 文档中的报告链接省略患者姓名等非必要参数，不记录手机号、患者资料或报告正文等敏感信息。验收证据按项目要求保存。
