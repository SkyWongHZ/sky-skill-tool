# 日报与周报

为用户生成可复制到钉钉日志的工作汇报。保留手动提供几天日报后整理周报的用法；从 Git 生成日报或配置自动任务时，读取 [自动日报与汇总规则](references/automation.md)。

本机已配置的八戒项目汇报资料位于 `/Users/sky_wang/Documents/工作日报与周报/`：`config.json` 为范围和偏好，`calendar.json` 为已核实日历，`state.json` 为采集及备忘录索引。处理该用户的八戒项目自动日报时优先读取这些文件；其他项目不套用此配置。

## 模型与用量偏好

- 提交筛选、按作者和日期归档、去重优先交给本地 `git` 和 GitLab `glab` 脚本；先读紧凑的提交摘要，只对描述含糊的事项补读必要 diff 或进度记录。
- 日报、周报的文字整理优先选用 `GPT-6.1 Sol`，低或中推理。默认不使用 Astra 批量查找和整理；只有用户明确要求，或任务复杂到现有模型无法可靠完成时才考虑切换。
- Skill 只能记录模型偏好，不能切换当前会话模型。定时任务是否能固定模型以其实际配置能力为准；未核实或未配置时不得声称已固定。若当前模型不符合偏好，告知用户并优先缩小读取范围；不要为了模型问题丢下已授权且可完成的日报。

## 选择输入

- 用户提供日报文本或文件：直接整理周报。
- 用户要求根据提交记录写日报：从已确认项目和作者采集证据，生成日报草稿。
- 用户要求定时生成：准备项目、作者、风格、日历和保存位置，再使用当前环境的自动任务工具配置。Skill 本身不负责唤醒执行。
- 优先使用用户指定文件；否则检查当前目录中明确命名为“日报”“周报”的原始文件。不要把任意 Markdown 当成日报；已有“整理”文件只作为风格或历史参考。

## 日期与范围

- 使用 `Asia/Shanghai` 日期，除非用户另有指定。
- 范围依次依据：用户明确指定的范围、材料中明确标注的日期、已配置的汇报周期。
- 有日期的日报按真实日期归档。缺一天、补写或一天多个段落都不能通过段落数量移动日期。
- 无日期且未指定范围时：周一默认上周一至周五；周二至周五默认本周一至当天；周末默认刚结束的周一至周五。在审阅说明中注明假设，存在跨周或假期歧义时询问用户。
- 节假日、调休与跨周期汇总遵循已确认日历，详见自动规则。不要默认周报必须包含五天。
- 周报文件名：`{年}.{月}.{日}-{年}.{月}.{日}周报整理.md`，月份、日期不补零。

## 内容与语气

- 优先模仿用户亲自提供或确认的历史日报；同事日志和截图仅用于了解版式，不能直接当成用户语气样本。
- 默认简洁、直接，使用“完成、调整、修复、梳理、核对”等具体动词，说明业务对象及结果。避免口号、泛泛的“持续推进”和大段实现细节。
- 按业务方向合并同类事项；同一需求的前后端改动可合为一项，但不同完成状态应保留。
- 保留具体成果、数量、业务影响及必要技术细节；不补造性能收益、测试结果、上线状态、百分比或预计完成时间。
- commit 证明存在代码变更，不自动证明功能完成、验收通过或已上线。仅有提交证据时写“调整/新增/修复……相关实现”，避免擅自加“已完成”。
- 已有明确完成证据时可写“已完成”；明确上生产的事项末尾加 `✅`。开发中事项保留用户给出的百分比，未给出时只写“开发中”。
- 保留已知阻塞的原因、影响和所需协助；不另套风险表格。
- 周报汇总同一事项的一周进展，使用最新的有依据状态；已解决的问题不继续写成阻塞，历史记录与用户修订冲突时以用户修订为准。
- 原文提供计划或用户要求整理计划时才增加“下周计划”；不从未完成事项推导承诺。

## 输出与审阅

日报默认格式：

```text
### 日报 {YYYY.MM.DD}

1. {业务事项及结果或已知状态}
2. {业务事项及结果或已知状态}
```

若用户确认使用钉钉“重点事项完成度（事项+百分比）”模板，仅填写有依据的比例；缺失比例放在正文外提示待补充，不默认填 100%。

周报保持原有格式：

```text
### 周报 {开始日期} - {结束日期}

#### {类别名}
• {工作项}：{有依据的进度或状态}
```

有计划材料时，在末尾增加“#### 下周计划”，继续使用 `•`。周报列表使用 Unicode `•`，避免钉钉粘贴时的列表渲染问题；没有状态证据时省略冒号和状态。

- 手动整理：写入当前目录或用户指定位置，并在对话中输出完整正文。
- 自动生成：按已配置目录保存日期明确的草稿，向用户展示正文及简短的待补充项。来源证据单独保存，不塞入可粘贴正文。
- 重跑时保留用户已修改或确认的文本；需要重新生成则另存带时间的修订草稿，并指出差异。
- 用户审阅后再形成确认版；此流程默认交付给用户审阅，不自动提交钉钉，也不发送给同事。
