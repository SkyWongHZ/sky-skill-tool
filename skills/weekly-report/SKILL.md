# 周报整理 Skill

## 角色
前端工程师，每周向 team leader 汇报工作进度。

## 执行步骤

### Step 1：确定时间范围
**优先按原始日报文件中的实际日报条数倒推日期范围**，避免周中提交时算错日期。

判定规则（按顺序）：
1. 先读取原始日报文件，统计其中**非空日报段落数 N**（一个段落 = 一天的日报，段落之间通常用空行分隔）。
2. 用系统时间获取今天的日期与星期：
   - 若今天是 **周一**：日报内容显然是上一个完整工作周的，结束日期 = 上周五，开始日期 = 上周一（结束日期 - 4 天）。
   - 若今天是 **周二 ~ 周五**：日报内容是本周的，结束日期 = 今天，开始日期 = 本周一（即 `结束日期 - (今天的周序号 - 1)` 天，周二减 1 天，周五减 4 天）。
   - 若今天是 **周六/周日**：视为对刚结束的工作周做总结，结束日期 = 上周五，开始日期 = 上周一。
3. 用 N 校验：若 `结束日期 - 开始日期 + 1 ≠ N`，以 N 为准，将 `开始日期 = 结束日期 - (N - 1)`。当 N 与日历推算冲突时，**信任 N**（用户可能漏写/补写某天，但条数最能反映实际覆盖范围）。

输出文件名格式：`{年}.{月}.{日}-{年}.{月}.{日}周报整理.md`
- 示例：`2026.3.9-2026.3.13周报整理.md`（月份和日期不补零）

### Step 2：读取原始文件
在**当前工作目录**查找原始周报文件：
- 优先找文件名不含"整理"二字的 `.md` 文件
- 若用户已指定文件路径，则直接使用

### Step 3：整理内容规则
- **合并同类项**：将相同业务方向的工作归入同一分类（如"设备相关"、"流量卡需求"、"定制需求"）
- **进度标注**：
  - 已完成并上生产 → 末尾加 `✅`
  - 开发中 → 原文有百分比时保留，如 `开发中 60%`；未提供时只写“开发中”
  - 已完成未上线 → 注明"已完成"
- **语言风格**：简洁清晰，不啰嗦，不重复描述
- **成果表达**：保留具体交付结果，以及原文已有的数量、性能改善或业务影响，避免合并时只剩“跟进”“优化”等笼统描述；不补造数据、收益、上线状态或预计完成时间。
- **阻塞信息**：原文有阻塞时，在对应工作项中保留原因、影响和所需协助；这些信息仅整理已提供的部分，不另套风险表格。
- **下周计划**：原文提供计划或用户要求整理计划时，可在末尾增加“#### 下周计划”，继续使用 `•` 列表，保留已明确的优先级与依赖；没有计划材料时不自动从未完成事项推导承诺。

### Step 4：输出格式
```
### 周报 {开始日期} - {结束日期}

#### {类别名}
• {工作项}：{进度/状态}

#### {类别名}
• {工作项}：{进度/状态}
```

> 注意：列表项使用 Unicode 实心点 `•`（U+2022），**不使用** Markdown 的 `-` 或 `*`，避免钉钉日报渲染乱码。

### Step 5：写入文件
将整理结果写入当前目录，文件名为 Step 1 确定的名称，同时在对话中输出完整内容，方便直接复制粘贴到钉钉日志。
